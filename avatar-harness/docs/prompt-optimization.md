# Prompt 与审校定向优化（2026-11-01）

上一批结果没有证实新版更好。此次把已有 U01–U06 改作开发回归集；另封存 V01–V06 六组十八轮，每组两次重复，在修改前保存文件哈希，源代码和二进制冻结后才首次运行。首次评测在第二组遭遇脚本提前退出；V01–V02 转作诊断，保留原始失败。最终验证使用其余 V03–V06 四组十二轮，各两次，共二十四个固定背景轮次/每个版本。它们在最终代码冻结前从未执行，结果不用于继续调试或挑选答案。

## 故障分类及对应机制

| 分类 | 已观察的故障 | 修改与可核验机制 | 验收 |
| --- | --- | --- | --- |
| 验收误判 | “不说祝贺”命中禁用词；问号无法判断是否重复索要证据 | 语义行为交给独立展示的语义评阅；词面规则明确只检查出现与否，保留旧原始分数 | `TestCalibrationSeparatesMeaningWordsRecordsAndSafety` |
| 验收混淆 | 正文两分钟合规，但没有行动记录，被叫成时间超限 | 行动记录与正文时限分开评阅；记录须有正分钟数，且记录片段实际存在于正文 | 同上及前端分类汇总测试 |
| Prompt | 默认 80–180 字、解释 3–6 句与当轮只确认/两句要求竞争；补造原因或偏好 | 本轮请求和负担上限优先，取消默认最低篇幅；只确认便结束；未知意愿保持未知；足够信息先分析 | 旧失败对话开发回放；新集候选稿逐轮复核 |
| 协议与记录 | 部分候选省略提交标记，生成调用被误记为成功 | 明确正文格式限制不取消外层 JSON/提交标记；成功状态延后到完整解析与提交门校验后；导出保留回退原因及细节 | `TestSupportComposeIncompleteJSONIsReportedAsFailure`（含缺失提交反例）及事件记录测试 |
| 审校 | 指定句数仅靠语义检查；批准稿也能漏过 | 对当前明确、非引用的句数与禁问要求作窄范围解析，候选批准前和修正版放行前都校验；失败只用原有一次有界纠错 | `TestSupportExplicitSentenceLimitRejectsApprovalBeforeRelease`、约束解析与计数测试、既有有界纠错失败测试 |
| 审校 | plan 在 speech 前，改写导致 action.text 不再匹配 | 修正版在同一次响应的 speech 后返回 final_action；引用、当前时限、意图及正文片段重新核对，只记 proposed，状态只推进一次；无效元数据不入库 | `TestSupportRevisionRecordsOnlyVerifiedFinalAction`，含伪造同意、正文不含动作、超当前时限反例 |

窄范围解析不是自然语言意图分类器。不识别的句式仍交给同一个最终审校器；正文所述耗时、建议可执行性、动机是否有依据仍需语义复核。自动句数按 `。！？!?` 与未闭合尾句计算，分号和小数点不算句末。

## 对照边界

主比较是“封存的优化前新版”与“优化后新版”，不是把历史旧版误当成优化前新版。两份服务使用相同模型、请求参数、角色、预置历史、感知夹具、记忆检索、支持状态和重复次数；每组交替两份服务的运行先后。两服务各自仍并行运行历史旧版与当前版，本次前后汇总只取其中 current 列；原始全部输出保留。

每轮使用共同参考答复承接下一轮，不采用某列刚生成的答复，属于固定多轮背景对照。两服务内部各共用一次风险检查，跨服务风险各自运行并记录是否一致。非实验输入在每份服务内校验指纹；跨服务核对完整场景、历史及除审校协议外的条件。新的审校协议指纹不同是实验变量，不能把跨服务完整指纹称为相等。

生成阶段更新行为/语音 Prompt，并在共享 compose 中补充正文限制不取消提交协议的说明；风险协议、方法卡和记忆解释未变。候选稿差异用于观察这些生成指令的合并作用，不能将其全部归于行为/语音文本。审校前后同一稿件的变化用于检查修正覆盖与伤害。整体前后结果包含 Prompt 与审校两项改动，不宣称全部增益仅来自 System Prompt；随机生成也会影响单条结果。

质量分成格式、词面、行动记录、安全与语义；不合并成一个“有效率”。语义复核由本助手完成，带具体问题说明，不是独立人工、盲评或临床评价。共同安全结果单列。延迟为服务端文字首段/完整完成，不是音频起播。75% 干预有效率口径仍待确认。

## 保留的链路

风险与生成保持并行，风险完成后才可放行；普通稿仅一次最终审校，合格候选按句流式输出，修正版完整校验后输出。仅机械约束失败且尚未放行时允许原有一次有界纠错，没有新增规划、语义复审或串行改写循环。渲染、感知、TTS、会话记忆和取消/过期结果隔离没有更换。

双栏页仍在 `/demo/prompts`，两列共用当前审校规则，分别用历史行为 Prompt 和优化后的当前 Prompt。该页面测量 Prompt 差异；本次封存旧二进制的额外前后对照用于测量整项优化。

## 最终验证结果

82 项前端测试、Vue 类型检查与构建、Go 全量竞态测试均通过。实际浏览器检查了分类汇总、逐项验收、评阅按钮、导出、桌面及手机布局；正常数字人渲染就绪，感知健康接口显示 LibreFace 2.0 AU 就绪。41 个既有会话保留，历史文件原有字节前缀哈希一致。部署二进制与冻结测试版本哈希一致。

最终 V03–V06 各重复两次，优化前后各 24 轮，其中普通/研究请求 22 轮、共同紧急路径 2 轮。两服务的场景、参考历史和非审校条件一致，风险结果全部一致。

语义复核是本助手的保守检查，逐项有理由，不是独立人工、盲评或临床验证。双方均正常完成的 19 对中，合格为 15→13，待核验各 2；因此本批**不能认定语义质量提升**。全体合格数略增主要受回退减少影响。新版仍有缺乏依据的流程规律、额外练习步骤、表情与情绪关系表达过强、情绪描述被过度归为过去/假设等问题。两版种植建议均因未确认排水条件而暂不判定可执行性。

首段等待全体略升、完整完成略降，不宣称显著提速。双方均正常完成的 19 对首段中位数 2.19→1.82 秒、完整 2.19→1.87 秒，仅是补充子集。调用数上升来自较少回退后更多轮次进入审校，以及一次额外纠错；不能把改写减少说成总调用减少。

V01–V02 的前期尝试和诊断回放全部另存。最初脚本错误地在失败时断言退出，有一次 V02 优化前错误快照未及时保存，已显式记录。补充正文/协议优先级说明后，诊断回放仍出现缺少提交标记；仅说明记录和拦截正确，不能称为已经消除。最终四组验证未出现该回退，也不能由此声称已根治。

完整可独立打开的逐轮双栏报告、原始候选与最终正文、复核理由、失败记录、冻结指纹和测试日志位于交付目录 `prompt-opt-20261101/`。75%有效率口径继续待确认。
