# 任务三的动态干预闭环与验收

根据新提供的项目任务截图，任务三要求监测交互过程中的情绪动态变化，在线调整刺激强度和切换调控策略，形成稳定、个性化的反馈闭环。截图列出的考核目标为干预方式至少三种、干预有效率至少 75%，同时明确注明有效率尚无官方定义。

三类支持路径与反馈控制器已接入：LLM 通过 `set_support_mode` 选择倾听/认知梳理/退出，通过 `start_mindfulness` 唤起正念视频。用户不需要配置方法；普通问答不启用支持。工具先安排，回答通过并完成语音生成后才提交，浏览器等实际语音播完再播放；取消、失败回答和历史事件不触发播放。普通页面保留“正念练习”按钮用于直接体验，参数面板只在开发页面展示。现有原话记忆、感知、渲染和语音链路保留。初版验收见 [历史记录](intervention-acceptance-20261031.md)，当前并行与流式实现见 [提速验收](intervention-speed-20261031.md)。正式效果评估协议仍待确认。

## 与前面五项能力的关系

[五项能力及风险处置](dialogue-mechanisms-and-acceptance.md) 支撑对话干预分支。苏格拉底式探索主要用于认知行为方法，倾听和用户目标确认也支撑人本支持路径。任务三还需要跨方法的反馈控制器，负责方法选择、呈现参数调整、效果回顾和停止。

```mermaid
flowchart LR
    O[话语、用户反馈、面部与声学观察] --> S[带来源与不确定性的状态更新]
    S --> C[方法与呈现参数选择]
    C --> G[风险、内容和取消准入]
    G --> M[视频或数字人对话执行]
    M --> F[用户反馈、目标变化与后续观察]
    F --> S
```

一般事实问答继续按当前任务直接完成。支持性方法的启用和切换结合用户意愿、明确目标及实际反馈。

## 三种候选方法及执行证据

| 截图中的方法 | 原型执行流程 | 可独立调节的参数 | 核对实际执行 |
|---|---|---|---|
| 正念方法，视频驱动 | 用户选择适用的注意练习，播放有来源的引导内容，在约定节点询问体验并允许随时停止。 | 内容 ID、练习时长、引导节奏、提示频率。 | 实际播放开始和结束、实际持续时长、用户是否中止、实际体验反馈。 |
| 人本支持，角色化对话驱动 | 反映用户具体处境，确认当前需要与目标，根据用户反馈调整倾听、澄清和建议的比例。 | 单次回应长度、主动提问频率、用户可接受的交流负担。 | 实际回应是否接住具体处境，用户明确只想倾诉时是否尊重这一需求，否认或纠正是否得到更新。 |
| 认知行为方法，角色化对话驱动 | 按用户当前意愿澄清情境、区分事实与解释、检查证据和其他解释，必要时共同确定小行动并回顾。 | 提问深度、每轮认知操作数量、小行动难度、回顾时机。 | 方法卡与来源、阶段选择、用户认可的行动、实际完成反馈及调整理由。 |

三条路径的区别通过具体行为、输入输出和反馈记录核对。候选方法的分类是否满足项目考核中的计数口径，需要在正式验收协议中确认。

## 表达强度与干预参数

当前 `emotion/intensity/speech` 中的 `intensity` 用于数字人的表情和 TTS 语气。该实现见 `internal/runtime/structured_answer.go`、`internal/runtime/speech.go` 和 [provider 协议](provider-contract.md)。

干预参数另行记录，包括练习时长、提问深度、交流节奏、提示频率和行动负担。不同方法的参数有各自的单位与边界，先验证每个参数的实际执行，再比较参数调整后的反馈。表情强度变化只作为表达行为记录。

每次调整记录具体变更参数、调整前后值、依据、用户意愿、方法版本和实际执行。尽量一次只改变一个参数，便于检查变化与反馈的关系。

## 状态依据与个性化

当前感知代码已可形成语句时间窗内的面部汇总和结尾观察，并接收本句声学标签。来源见 `internal/runtime/perception.go`。它们提供行为观察，真实情绪与干预体验仍需结合用户话语和反馈判断。

状态更新区分用户明确自述、行为观察、待确认解释和实际行动结果，保留各自来源与时间。缺失、多来源冲突、无脸、过期等情况单独记录。模型分数保持未校准标识，不能自行解释成心理状态概率。

个性化以用户确认的目标、偏好、可接受负担和过往实际反馈为依据。第一阶段在同一会话内验证，跨会话个性化还需明确身份关联和使用范围。用户个人记录与通用方法知识库分别管理。

## 反馈控制规则

| 反馈条件 | 候选控制动作 | 需要的依据 |
|---|---|---|
| 用户要求停止，或出现应优先处理的危险情况 | 停止当前路径，进入适当的支持和现实求助流程。 | 当前话语、适用风险判断和取消身份。 |
| 用户明确表示太累、太快、不舒服或不愿继续 | 降低具体负担、暂停或共同选择其他方法。 | 原话和当前方法参数。 |
| 用户报告有帮助且愿意继续 | 保持当前方法，按目标和意愿决定维持或逐步结束。 | 当前反馈、目标进展和完成情况。 |
| 到约定回顾点后，用户确认持续没有帮助 | 检查执行情况与适配性，再共同选择调整参数或更换方法。 | 实际执行、反馈和可用替代路径。 |
| 观察缺失、相互冲突，或用户没有提供必要反馈 | 保持低负担交流，必要时简短询问体验。 | 数据质量标记和当前明确任务。 |
| 只有面部或声学标签短时变化，用户目标及反馈未变 | 对信号作平滑或等待更多观察，保持方法选择稳定。 | 原始观察窗口、变化记录和用户反馈。 |

为减少反复切换，控制器需要参数边界、单次调整上限、最小观察区间和切换条件。用户停止与风险处理优先于这些等待规则。具体参数通过重放测试和实际反馈校准，不能仅凭控制器设置宣称用户情绪已经稳定。

## 可验证的闭环用例

| ID | 输入或过程 | 验收对象 |
|---|---|---|
| L01 | 分别选用三种候选方法。 | 每条路径都有实际执行、体验反馈和回顾记录。 |
| L02 | 用户当前只需要一个事实答案。 | 完成当前问题，方法选择符合用户意愿。 |
| L03 | 保持用户话语与反馈相同，仅替换或移除传感器标签。 | 不凭标签改变对个人经历和效果的事实判断。 |
| L04 | 重放高低交替的短时预测噪声。 | 参数有界，切换符合条件，不因单帧波动频繁切换。 |
| L05 | 用户表示练习太长或问题太多。 | 调整时长、提问频率等实际参数，核对下一轮执行。 |
| L06 | 调高数字人的表情强度。 | 仅记录表达变化，干预参数和效果记录按各自依据更新。 |
| L07 | 在播放、生成或效果检查过程中停止，旧结果随后返回。 | 旧语音、视频和状态结果均不进入新轮。 |
| L08 | 已执行的方法得到有帮助、无帮助和变差三种反馈。 | 分别产生有来源、可解释的维持、重新协商或停止动作。 |

这些用例已分别加入 Go 与前端验收，浏览器检查补充真实视频帧、播放计时、反馈与会话切换证据。初版多轮模型对照测量文字等待；后续新增两次浏览器实际起播，详见提速验收，仍不能代替真实语音三秒验收。

## 干预有效率的口径

75% 先登记为项目目标值。正式试验前应确认评价单位、对象范围、改善标准、观察时点、比较条件和缺失数据处理方式。

若采用参与者响应率，可供项目方讨论的公式为达到预设改善标准的参与者人数，除以纳入评估的参与者总人数。退出、未完成和缺失单列报告，其主分析处理方式提前确定。若项目考核采用每次干预或其他单位，应相应更改公式和统计方案。

改善标准以与任务匹配、事先确定的用户自评和目标或行为结果为主要依据。面部、声学变化和模型判断分别作为辅助结果报告。回复满意、完成一次行动和持续情绪改善也分别记录。

对照至少覆盖固定方法或普通支持性交流与动态控制方案，尽量保持底座模型、界面、可用内容和评价时点一致。这样可以考察动态选择与调节是否带来额外帮助。先完成工程重放与留出用例，再通过获得适用授权的真实使用数据评估结果，报告样本量、响应率及不确定性。

## 当前实现与使用

普通页面由 LLM 工具选择倾听支持或认知梳理，并可唤起正念视频；顶部“正念练习”按钮用于直接体验。侧栏方法与参数面板仅在开发页面显示。随时可以停止当前练习、结束支持或切换会话。重放历史不会自动播放视频。

视频在主舞台渐入，LAM 人物平滑缩小并移至右下角，以透明背景叠加；停止或练习结束后回到原位。侧栏收起不影响已开始的播放，舞台“返回对话”和底部停止键均可退出。位置切换复用同一个人物渲染器，尊重系统减少动态效果的设置。

主舞台的“正念练习”按钮直接按视频完整时长开始。播放画框保持 16:9，数字人和视频共用这一画框，底部控制栏放在画框外；宽高受桌面窗口可用空间约束，保留原始比例与完整画面。

本机可在配置中指定 `practice_video`：`path` 为 MP4 绝对路径，`title` 为名称，`duration_seconds` 为 60–300 秒，`has_audio` 控制原音轨，`source_url` 记录来源。`GET /api/state` 返回展示元数据；`GET /api/practice-video/file` 支持 HTTP 字节范围读取和拖动定位，不把整段视频读入内存。媒体放在 `.avatar-harness/media/`，不编入可执行文件、不提交 Git。没有配置时仍可用原有的光点演示片。

当前本机接入中大 GoSmart 的《三分钟呼吸空间练习》，4 分 24 秒、1920×1080、H.264/AAC。下载副本与 SHA256、来源记录保存在本机媒体目录。版权归原作者；复制、修改、分发等用途须遵守[原站条款](https://www.chep.cuhk.edu.hk/gosmart/video/606525fce6693#terms-modal)，此处不声明获得了再分发许可。

`internal/intervention` 管理独立参数、方法卡、状态和反馈规则；`internal/runtime/support_pipeline.go` 负责并行的风险检查与候选生成，以及合并状态整理的一次审校。批准正文按句进入 TTS；修正文完整校验后放行。只有尚未放行正文且违反字数或问题数量等程序约束时，允许一次定向纠错，复用已验证状态，不循环重写和复查。失败会明确回退，已放行的部分回复则如实保留并标为部分结果。正常工具调用与 `<speak/>` 提交约束继续使用。

参数单位与边界：视频时长 15–300 秒、画面速率 0.75–1.25；每次回应 60–400 字；提问深度 0–2；每 1–4 轮至多一个问题；小行动最多 1–5 分钟。时长与速率直接用于播放器，字数和问题数量有程序检查，提问深度与行动适配另经语义检查。表情的 `intensity` 未作为这些参数的输入。

有帮助时维持；负担偏大时仅降低一个实际参数；连续两次无帮助时提出替代方式并等待用户选择；变差时暂停。用户实际体验反馈来自按钮或具有当前原话依据的话语，传感器分数不触发效果判定或方法切换。视频记录客户端观察到的可见、持续前进的播放时间，排除暂停、卡顿和后台时间。记录属于客户端执行证据，不能证明用户注意程度或疗效。

支持状态与对应最终对话以一个日志记录提交，版本不符时丢弃，避免取消后的迟到结果更新当前状态。清空、会话隔离、重启恢复与中断有对应测试。跨会话身份关联、真实临床数据、正式疗效试验与新增工具均未纳入本次实现。
