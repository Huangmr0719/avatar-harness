# 对话行为与会话记忆

数字人按通用助手定位交流。事实问题先回答，复杂问题按需要说明理由、步骤和取舍，探索性提问用于帮助用户梳理具体问题。语音回答采用短句，篇幅随当前问题和用户要求调整。行为提示词位于 `internal/runtime/prompt.go`。

表情提示词位于 `internal/runtime/structured_answer.go`。日常情感采用较低强度，安慰可以使用平静中性表达。用户明确要求表情演示时仍执行对应表情和演示强度。输出继续采用 `emotion/intensity/speech`，正文由 `<speak/>` 提交，工具决策和内部思考遵循现有隔离协议。

模型偶尔在 JSON 字符串中输出未转义的换行，流式解析器会规范化字符串内的换行、回车和制表符，模型历史保存合法 JSON。旧 provider 的纯文本兼容回复仍按原方式交给页面和 TTS，模型侧历史补成中性三字段对象，帮助后续轮次维持格式。该补齐只用于历史格式，不代表模型提供了表情参数。

## 记忆的数据与更新

记忆限定在同一会话内，复用本地 `sessions.jsonl`。每轮自动注入以下内容。

- 最近对话，窗口沿用 `limits.max_history_messages`，默认 20 条，保持完整工具回合。
- 按目标、约束、偏好、明确决定、待解决问题、已认可行动、交流边界和纠正分类的原话条目，最多 12 条。
- 从较早用户消息中按字词相关性和时间检索的原话，最多 8 条，每条最多 600 字。较长消息取相关词附近的片段。

每项记忆附从 1 开始的来源消息序号。原话必须与本会话 user 消息逐字匹配，单项保留最多 160 字。必要的前文由程序从来源之前的助手回复中取得，最多 240 字，帮助理解“好，就这样”或指代。助手上下文供解释原话使用。

窗口外新增记录累计至少 8 条消息时，在最终正文提交后启动一次后台整理。一次处理最多 24 条较早消息，并向前延伸至完整回合边界。每条整理输入最多 2,000 字。整理使用现有 LLM 和独立 JSON 协议，8 秒超时，禁用工具，输出不进入正文、TTS 或普通对话历史。

用户当前话语与最近修正优先于旧记忆。整理模型负责替换或移除过时条目，程序检查类别、数量、来源序号和逐字原话。`support_preference` 保留明确交流边界；`correction` 可用 `replaces: [{message, quote}]` 标识较早、确实存在的旧原话片段。程序累积 `superseded`，在条目注入和历史检索中屏蔽被替代的片段，即使之后的 12 条选择省略纠正，也不让旧片段复活。未改变的条件仍可检索，历史原文不删除。替代关系的语义仍可能有模型误差，来源合法不等于理解正确。整理失败时保留已有记忆，其余历史原话继续可检索。机制和验收边界见 [人本支持](humanistic-dialogue.md)。

新输入或停止操作取消该会话的后台整理。保存前同时检查任务身份、取消状态和历史长度。`/clear` 同时清空历史和记忆。旧日志可直接使用，首次需要时逐步整理。OpenAvatarChat 调用者传入的历史保持由调用者管理。

摄像头和声学观察继续作为本轮短时感知输入，不交给记忆整理器。来源和更新协议见 [camera-perception.md](camera-perception.md)。

## 后续本地知识库

五项能力与风险处置分别对应的机制、状态字段和验收用例见 [逐项机制与验收设计](dialogue-mechanisms-and-acceptance.md)。该设计区分已实现的原话记忆与后续状态控制、方法检索、行动回顾和风险准入。

可把认知行为方法整理为带来源的小型方法卡，字段包括适用情境、交流目标、提问方式、用户可选的小行动和反馈方式。候选内容包括澄清具体情境、区分事实与解释、检查证据、探索替代解释，以及共同回顾行动结果。

检索到的方法卡可作为本轮参考材料注入，与用户会话记忆分别标识。先按使用情境筛选小规模材料，再根据实测决定是否需要向量检索。通用助手根据当前需求和用户意愿选择使用方式，知识库效果通过具体对话任务评估。

方法设计参考 [Socratic Inquiry Framework](https://arxiv.org/html/2602.01598v1) 的策略与提问方式选择，以及 [DMT-CBT](https://arxiv.org/html/2606.03132v1) 的状态、记忆和行动连续性。两篇论文的原实验包含模型训练或微调。本项目这一阶段采用行为提示词、带来源的会话记忆和本地原话检索。
